# Project Documentation: VR Match the Object

## AI Use Declaration

During the development of this project, Artificial Intelligence (AI) was utilized as a technical collaborator and design assistant, working alongside our development team. The scene design, overall software architecture, component assembly in Unity, and testing on the headset (Meta Quest) were led, executed, and manually validated by us. The AI did not generate the complete project automatically; rather, it served as a pair-programming tool to optimize code snippets, discuss best practices for Virtual Reality interfaces, and resolve specific logic and version control queries.

* *"We noticed that resetting the object's properties one by one could be repetitive. Is it better practice to store the initial state in variables during `Start()` and restore them, or should we instantiate a new prefab? What are the performance implications in Unity VR?"*

## Implementation Explanation

The project was built using Unity and the XR Interaction Toolkit for Meta Quest, structured into the following phases:

1. **Scene Setup:** Implemented a base VR scene with two main elements: the `PlayerObject` (which the player modifies) and the `TargetObject` (the pre-configured visual goal with a specific shape, color, size, and rotation).

2. **Modification Logic (Scripts):** Created the `ObjectModifier.cs` script assigned to the `PlayerObject`. This script contains public methods to instantly change the `MeshFilter` (Shape), the `MeshRenderer` material (Color), the local scale (Size), and the rotation in 45-degree increments along the spatial axes.

3. **Validation Logic:** Developed the `MatchValidator.cs` script inside a `GameManager`. This component compares the current properties of the `PlayerObject` with those of the `TargetObject`. To avoid frustration in VR, a 30-degree rotation tolerance was implemented using `Quaternion.Angle`, along with logical exceptions (such as ignoring rotation if the object is a sphere).

4. **VR User Interface (World Space UI):** Built a floating Canvas configured in World Space mode and integrated with a `Tracked Device Graphic Raycaster` to allow interaction with the Quest controller lasers.

5. **Button Structure and Connection:** The panel was organized using `Vertical` and `Horizontal Layout Groups` into 5 rows (Shape, Color, Size, Rotation, and Actions). Each of the resulting 14 buttons was manually connected from the Inspector to the `OnClick()` event, passing integer parameters (0, 1, 2) to the `ObjectModifier` to execute the corresponding visual change without requiring multiple individual scripts.

6. **Version Control:** The project was integrated using Git by syncing an appropriate remote `.gitignore` for Unity, preventing the upload of heavy local folders like `Library`, and ensuring a clean repository state before pushing to the main branch.
